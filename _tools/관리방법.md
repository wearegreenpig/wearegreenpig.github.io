# 그린피그 웹사이트 관리 방법

## 폴더 구성

| 파일 | 내용 |
|---|---|
| `index.html` | 첫 페이지 (로고, 메뉴, 최근 소식 세 줄) |
| `about.html` | 소개 |
| `people.html` | 사람 |
| `texts.html` | 텍스트 (관객 리뷰·기사, 비평, 그린피그에 관한 글) |
| `archive.html` | 아카이브 (연도별 공연 목록, 기타 공연·낭독, 수상) |
| `w번호.html` | 작품별 페이지. 번호는 드라이브 「1_공연정보」 폴더 번호와 같습니다 |
| `w번호.jpg` | 작품 포스터 (가로 600px 정도로 줄인 것) |
| `who.html` | 참여 기록. 사람별 참여 작품 목록 (build.py가 크레딧에서 자동으로 만듦) |
| `chronology.html` | 인쇄용 공연 연보 (build.py가 자동으로 만듦, 인쇄·PDF 저장용) |
| `theaters.html`, `writers.html` | 극장별·작가별 색인 (build.py가 공연 자료에서 자동으로 만듦) |
| `search.html`, `search.js` | 찾기 페이지와 그 색인. 색인은 build.py가 작품·사람·극장 자료로 자동으로 만듭니다. 첫 페이지 메뉴의 '찾기'는 링크처럼 생긴 입력칸이라, 누르고 글자를 쓴 뒤 엔터를 치면 이 페이지로 결과가 넘어옵니다 |
| `rotator.js` | 소개 페이지 첫 화면에서 작품 제목을 1초마다 바꿔 보여 줍니다. 제목 목록은 build.py가 `about.html`의 `<!-- 제목 돌리기 -->` 사이에 자동으로 넣습니다 |
| `texts.js` | 텍스트 페이지의 보기 고르기(작품별·글쓴이별·최근 순, 평론·기사·관객 후기). 자료는 build.py가 `texts.html`에 넣습니다 |
| `random.js` | '아무 작품이나' 링크용 작품 목록 (자동 생성) |
| `style.css` | 색과 여백 |
| `theme.js` | 밤낮 전환. 첫 페이지 로고를 누르면 다크모드가 바뀌고, 그 선택이 다른 페이지에도 이어집니다 |
| `game.js`, `pig-data.js` | 숨은 놀이 「돼지 달리기」. 첫 페이지 로고를 빠르게 다섯 번 누르면 열립니다. 코스(`pig-data.js`)는 build.py가 공연 기록으로 자동으로 만들므로, 새 공연을 `works_data.py`에 넣고 build.py를 돌리면 게임에도 그대로 붙습니다 |
| `en/` | 영어판. build.py가 `_tools/works_data_en.py`의 번역으로 자동으로 만듭니다(손으로 고치지 마세요). 모든 페이지 오른쪽 위의 English/한국어 링크로 오갑니다 |
| `fonts/` | 글꼴 Pretendard(SIL OFL). 쓰인 글자 묶음만 내려받습니다 |
| `_tools/` | 작품 페이지를 한꺼번에 만드는 도구. 웹에는 공개되지 않습니다 |

## 손으로 바로 고쳐도 되는 것

GitHub 저장소에서 파일을 열고 연필 아이콘(Edit)을 눌러 고친 뒤 **Commit changes**를 누르면 1~2분 뒤 사이트에 반영됩니다.

- **최근 소식**: `index.html`의 `<!-- 새 소식은 ... -->` 아래 맨 위에 `날짜 제목 / 공연장` 한 줄을 넣고(제목에 작품 페이지 링크), 맨 아래 줄을 지웁니다(세 줄 유지, 아카이브 목록과 같은 모양).
  ```
  2027.3.1–10 <a href="w72.html">새 작품</a> / 극장<br>
  ```
- **사람**: `people.html`에서 이름을 더하거나 옮깁니다.
- **소개**: `about.html`의 문단을 고칩니다.
- **비평, 그린피그에 관한 글**: `texts.html`의 해당 부분에 한 줄을 추가합니다.

## 작품·공연·리뷰를 더할 때 (권장: Claude에게 맡기기)

작품 페이지, 아카이브, 텍스트 페이지의 리뷰 목록은 `_tools/works_data.py`에 적힌 자료로 `_tools/build.py`가 한꺼번에 만듭니다.
그래서 이 세 가지는 **`works_data.py`를 고친 뒤 build.py를 다시 돌리는 것**이 맞는 방법입니다.
`w번호.html`이나 `archive.html`을 손으로만 고치면 다음에 build.py를 돌릴 때 덮어써집니다.

가장 쉬운 방법은 Claude에게 이렇게 말하는 것입니다.

> 그린피그 웹사이트 저장소(wearegreenpig/wearegreenpig.github.io)에 새 공연 추가해줘.
> 〈제목〉, 2027.3.1–10, 극장, 누구 작·연출. 포스터 첨부. 소개는 이거: …

Claude가 `works_data.py`를 고치고, build.py를 돌리고, 저장소에 올립니다.

### 직접 할 때

1. `_tools/works_data.py`의 `PERFORMANCES`에 한 줄 추가
   ```
   72|2027.3.1–10|새 작품|누구 작, 누구 연출|극장 이름|비고
   ```
   (번호|날짜|제목|작·연출|공연장|비고. 재공연은 같은 번호로 한 줄 더)
   아카이브 목록에는 날짜·제목·공연장만 나오고, 작·연출과 비고는 작품 페이지와 인쇄용 연보에 나옵니다.
   작품 페이지 없는 낭독·행사는 `PERFORMANCES` 대신 맨 아래 `OTHER`에 `날짜 〈제목〉 작·연출 / 공연장 - 비고` 한 줄로 적습니다.
2. 소개·크레딧·리뷰는 파일 맨 아래에 추가
   ```python
   add("72", 소개="…",
       크레딧=[("작", "…"), ("연출", "…"), ("출연", "…")],
       리뷰=[("2027.3.5", "https://…", "관람 후기", "네이버 블로그")])
   ```
3. 포스터는 `w72.jpg`로 저장
   소개가 길면 `"""…"""`로 감싸고 빈 줄로 문단을 나눌 수 있습니다.
4. 사이트 폴더에서 `python3 _tools/build.py` 실행 → 바뀐 파일 전부 저장소에 올리기

## 리뷰·평론의 글쓴이와 종류

리뷰 한 줄은 `("날짜", "주소", "설명", "출처")`이고, 다섯째 칸에 글쓴이를 적을 수 있습니다: `("2024.2.7", "https://…", "리뷰", "매일신문", "김건표")`.
이경미·김옥란 블로그 주소처럼 `works_data.py`의 `WRITERS`에 있는 주소는 글쓴이가 자동으로 붙습니다.
`CRITICS`에 있는 글쓴이의 글과 설명에 '비평'·'평론'·'단평'이 들어간 글은 평론, '기사'·'소개'·'칼럼'이나 언론사 출처는 기사, 나머지는 관객 후기로 분류됩니다.
새 평론가를 더하려면 `CRITICS`에 이름을, 블로그가 있으면 `WRITERS`에 주소를 한 줄 더하세요.

## 작품명 괄호

링크가 걸린 작품명은 파란 글씨로 구분되므로 〈 〉 없이 보여 줍니다. 손으로 〈제목〉이라고 적어도 finish.py가 링크 안의 괄호를 자동으로 뺍니다. 링크 없는 작품명과 인쇄용 연보에는 괄호를 남깁니다.

## 참여 기록과 이름 링크

`build.py`는 각 공연의 작·연출 줄과 작품별 `크레딧`에서 이름을 모아 `who.html`을 만들고,
사람 페이지와 작품 페이지의 이름에 링크를 겁니다. 사람 페이지에 새 단원 이름을 적어 두면,
그 사람이 크레딧에 한 번이라도 오른 뒤 build.py를 돌릴 때 자동으로 링크가 생깁니다.
크레딧은 "이름, 이름" 형식으로 쉼표로 나눠 적어 주세요. 배역은 `전선우(데스데모나)`처럼 붙여 씁니다.

## 첫 페이지 "N년 전 오늘"

첫 페이지 소식 아래에 지난 공연 가운데 오늘 날짜에 개막했거나 공연 중이던 작품이 최대 두 줄 나옵니다.
build.py가 공연 날짜로 자동으로 만들며, 해당 작품이 없는 날은 보이지 않습니다.

## 극장 이름 통일

같은 극장이 다르게 적힌 경우(예: "대학로 정보소극장"과 "정보소극장")는 `build.py`의 `VENUE_SAME`에 한 줄 추가하면 극장별 색인에서 하나로 묶입니다.

## 대표 공연 사진

작품마다 공연 사진 한 장을 `w번호s.jpg`(예: `w13s.jpg`, 가로 1000px 정도)로 저장하면 포스터 아래에 나옵니다.
사진 아래 작은 글씨는 `works_data.py`에 `add("13", 사진="2019 CJ아지트 · 사진 이름")`처럼 적습니다.
사진을 바꾸려면 같은 이름으로 덮어쓰고, 빼려면 파일을 지우면 됩니다.

## 자동으로 붙는 것

`build.py`를 돌리면 마지막에 `finish.py`가 모든 페이지에 다음을 넣습니다. 손으로 고칠 필요 없습니다.

- 탭 아이콘(`favicon.png`), 카톡·X 공유 미리보기(제목, 설명, 이미지). 작품 페이지는 포스터가, 나머지는 `og.png`가 미리보기 이미지로 쓰입니다.
- 맨 아래 "발행일". 내용이 바뀐 페이지만 날짜가 새로 찍힙니다(`_tools/수정날짜.json`에 기록).

GitHub에서 페이지를 손으로 고친 경우에는 다음에 build.py(또는 `python3 _tools/finish.py`)를 돌릴 때 날짜가 갱신됩니다.

## 주의

- 단원 연락처, 주소, 계좌, 생년월일 같은 개인정보는 절대 올리지 않습니다. 사람 페이지는 이름과 역할만.
- 블로그 글이나 비평문 본문은 옮겨 싣지 않고 링크·서지만 적습니다.
- 저장소는 공개(Public)입니다. 올린 파일은 누구나 볼 수 있습니다.

## 나중에 도메인을 살 때

`greenpig.kr` 같은 주소를 사면(연 2~3만 원) GitHub 저장소 **Settings → Pages → Custom domain**에 적고,
도메인 업체 설정에서 안내대로 연결하면 같은 사이트가 새 주소로 열립니다.

## 포스터가 여러 장인 작품

재공연 등으로 포스터가 여러 장이면, 첫 장은 `w○○.jpg`, 다음부터 `w○○-2.jpg`, `w○○-3.jpg` … 로 저장합니다.
`_tools/works_data.py` 맨 아래에 `add("○○", 포스터=["2012 정보소극장", "2022 대학로예술극장 소극장", …])` 처럼
같은 순서로 언제·어디 포스터인지 적으면 작품 페이지에 나란히 나오고, 설명은 그림 설명(alt)과 마우스를 올렸을 때 보입니다. (가로 1000px 안팎이면 충분)

## 발행인

`colophon.html`(발행인 페이지)과 `humans.txt`는 메뉴에 없습니다. 모든 페이지 맨 아래 "발행일" 글자가 링크입니다.

## 참여 기록의 연도와 동명이인

- 참여 기록(who.html)에는 그 사람이 실제로 참여한 공연의 연도가 붙습니다. 공연 기록 줄의 크레딧은 그 회차 연도로,
  `works_data.py`의 크레딧은 역할에 `출연(2022)`, `2026 출연`처럼 연도를 적으면 그 연도로 잡힙니다.
  연도를 안 적은 크레딧은 같은 작품의 `출연(연도)`를 따르고, 그것도 없으면 첫 공연 연도가 됩니다.
- 이름이 같은 다른 사람은 `_tools/build.py`의 `SAME_NAME`에 한 줄 추가합니다.
  예: `("박정근", "사진", "박정근(사진)")` → 역할에 '사진'이 들어간 박정근은 '박정근 (사진)'으로 따로 모입니다.
- 참여 기록에는 역할만 깔끔하게 나옵니다. 괄호 속 설명(배역명, 연도, 공연명)은 작품 페이지 크레딧에만 보이고,
  '배우·연기'는 '출연'으로 묶입니다. 묶을 표기를 더하려면 `build.py`의 `SAME_ROLE`에 추가하세요.

## 영어판

`en/` 폴더의 영어 페이지는 build.py를 돌릴 때 함께 만들어집니다. 번역은 `_tools/works_data_en.py`에 있습니다.

- **새 작품**: `TITLE`에 영어 제목, `INTRO`에 영어 소개를 한 줄씩 더하세요. 없으면 한국어 제목을 로마자로 옮겨 임시로 씁니다.
- **새 극장·비고**: `VENUE`, `NOTE`에 더하세요. 없으면 한국어가 그대로 나옵니다.
- **사람 이름**: 성 + 이름을 자동으로 로마자로 옮깁니다(예: 윤한솔 → Yoon Hansol). 본인이 쓰는 영문 이름이 다르면 `NAME`에 `"이름": "영문 이름"` 한 줄을 더하세요.
- **첫 페이지 소식**: 한국어 `index.html`의 소식 세 줄을 영어판이 그대로 옮겨 씁니다(제목·극장은 번역).
